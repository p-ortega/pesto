<objective>
Clear the package-legitimacy gate before a single dependency is installed.

RESEARCH.md's `## Package Legitimacy Audit` ran the automated checker against all eleven PyPI
packages this phase introduces and every one came back `SUS`. The researcher's own inspection shows
why — for the PyPI ecosystem the checker cannot read weekly-download counts (`weeklyDownloads` is
`null` even for numpy) and its `publishedAt` field carries the latest release date rather than the
package's age, so any mature project that shipped a point release recently reads as "too new". The
researcher dispositioned all eleven as **Approved false positives** and recommended a single
lightweight human confirmation rather than one checkpoint per package.

This plan is that single confirmation. It exists because a package-legitimacy checkpoint is never
auto-approvable, and because the alternative — a planner silently overriding eleven `SUS` verdicts —
is exactly the un-decided hole the gate is there to close.

Purpose: no install command runs in this repository until a human has looked at the dependency set.
Output: a recorded approval (or a corrected package list) that plan 01-02 writes into `pyproject.toml`.
</objective>
